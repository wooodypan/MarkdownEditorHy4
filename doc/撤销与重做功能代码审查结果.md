## 🔴 重大缺陷 1：换文档不清撤销栈 —— 有真实的数据损坏路径

全项目只有 `toggleCollapse` 调 `undoManager?.removeAllActions()`。而 `MarkdownDocumentViewController.apply()`（约 562–586 行）在「预览 Tab 被复用成另一份文档」时，对**同一个 editor 实例**直接 `setMarkdown(item.body)`，撤销栈原封不动。

后果推演（不是理论，是必然发生的链路）：

1. 用户在文档 A 里打字、粘贴（栈里留下 A 的系统条目 + 快照条目）；
2. Tab 复用切到文档 B（`openedFileURL` 已指向 B 的文件）；
3. 按 ⌘Z → 快照条目把**文档 A 的整篇内容**恢复进当前编辑器；
4. 按 ⌘S → `editor.markdownSource` 被存进 **B 的文件** → B 被 A 覆盖，静默数据损坏。

更早的系统裸条目（按 A 的渲染文本坐标记的范围）套在 B 的文本上还可能越界/错位，reconcile 会把差异直接灌进 B 的源码。

讽刺的是，`toggleCollapse` 清栈的注释自己写明了道理：「栈里更早的记录是针对旧渲染文本的，撤销它们会污染源码」——**整篇换文档比折叠更彻底地让旧账作废，却漏掉了**。修复很便宜：`apply()` 里换文档时（`!isSameDocument`）加一句清栈；注意不能放进 `setMarkdown` 本身，因为 `restoreDocument` 也靠它。

## 🔴 重大缺陷 2：代码里对「系统是否给程序性替换记账」的假设互相矛盾

两处注释不能同时为真：

- `applyEdit` 路径 A 用 `disableUndoRegistration` 消音，理由是「不消音系统会**再记一笔**」→ 暗示系统会给程序性 storage 替换记账；
- `toggleCollapse` 注释说「折叠写的这一段**会被系统记进撤销栈**」；
- 但路径 B（`isProgrammaticEdit = true`）的写回**完全不消音**，`restoreDocument` / `setMarkdown` 的整篇替换也不消音。

如果前两处观察属实，那么一次真实 ⌘V 粘贴 = 快照条目 + 系统裸条目**两笔账**：用户要按两次 ⌘Z，且裸条目在快照恢复后的文本上执行会错位污染源码；撤销时 `restoreDocument` 的替换还会被记进重做栈，和我们登记的 R1 形成双份。如果实际系统只给「用户输入事件」记账，那 `toggleCollapse` 清栈的真正理由就另有其事。**至少有一处代码建立在错误的行为假设上**。

现有测试没抓住这一点的原因很明确：它们都直接调 `insertMarkdownSourceUndoably()` API，**不走真实的 ⌘V 键盘事件路径**——而 `_UITextUndoManager` 的记账行为很可能恰恰依赖「是否在用户事件内」。建议补一个走 `insertText`/真实 paste 路径的实证测试钉住行为，再统一三处策略。

## 🟠 高危 3：多 Tab 下 UndoManager 归属未验证

测试注释写明「UndoManager 是从响应者链上取的（view → superview → window → …）」。右栏是 MultiTabController 多 Tab，多个编辑器同挂一个 window。**如果栈是 window 级共享的**：Tab B 里 ⌘Z 可能执行 Tab A 登记的条目（target 是 A 的 editor）→ 静默修改看不见的文档；关掉 Tab 后条目仍强引用旧 editor → 泄漏 + 「按撤销没反应」。`TempUndoChainTests` 打印 `ObjectIdentifier` 显然就是在查这件事，但两个用例**没有任何断言、结论也没落盘**（顺带：我这次 `-only-testing` 指定它时它压根没被执行）。整个设计隐含「栈属于本编辑器」的前提，这个前提没被钉住。

## 🟡 中危 4：撤销栈无上限 + 整篇快照，内存无界增长

`levelsOfUndo` 默认 0 = 无限。路径 B 每笔记**两份整篇源码**（`previousSource` + 闭包捕获的 `currentSource`）。大文档上连续 ⌘B/替换，几百条快照轻松累积上百 MB。建议设 `undoManager?.levelsOfUndo = 50~100`（一行改动，系统自动丢弃最旧的账）。

## 🟡 中危 5：复选框切换不可撤销

`toggleCheckbox` 只设 `isProgrammaticEdit`，没套 `performUndoableModelEdit`。用户勾掉一个任务后按 ⌘Z，撤销的是**更早的另一件事**，勾选纹丝不动——违反直觉且可能引发误操作连环撤销。修复就是包一层 `performUndoableModelEdit(actionName: "切换任务状态")`。
