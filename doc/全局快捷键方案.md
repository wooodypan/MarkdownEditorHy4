> ### 和「SettingsViewController的示例」那一章的四处差别（都不是随手改的）
> 1. **Mac 的侧边栏和面板都没套 `UINavigationController`**。示例两边都套了，为的是详情页能有个导航栏放返回按钮；我们的设置窗口自己有一根标题栏，再套一层就是「标题栏 + 导航栏」两个头、白白占掉一条。分栏本来也不需要返回 —— 换分组点左边一下。
> 2. **面板的表里没有分组标题**（示例每页自带标题）。一块面板只有一个分组，名字已经由外面那层显示了（iOS 是导航栏标题，Mac 是侧边栏里高亮的那一行），表里再画一条同样的灰字标题属于重复。
> 3. **示例是每个分组各写一个 `ViewController`**（`GeneralSettingsViewController` / `AccountSettingsViewController`…）。本工程是「同一张表 + 一份行清单」拼出来的，所以只有 `SettingsPaneViewController` 一个类，靠 `section` 参数区分 —— 照示例那样七个分组就得写七个类，往后加一行设置要改两处。
> 4. **示例里那个路由器 `SettingsViewController.make()` 的位置**：本工程原来叫 `SettingsViewController` 的类是「页面」本身（拆分后成了 `SettingsPaneViewController`），所以没再起一个新类型，把「长什么样」和「怎么打开」都收在既有的入口 `SettingsOpener` 里。
>
> 附带一条：工程里**没有 `Settings.bundle`**，所以系统不会自带「设置」菜单项（Apple 的规矩是「带 Settings.bundle 的 Catalyst App 才自动获得设置窗口和那一条菜单项」）。有朝一日加了这个 bundle，⌘, 就会被系统那条占掉、我们再加就撞车。
>
> ### 四个坑（都踩过，改这块之前先看）
> 1. **`UIApplicationSupportsMultipleScenes` 必须为 `true`**（本工程原先写死 `false`，已改）。关着的话系统根本不给第二个窗口，`requestSceneSessionActivation` **静默失败** —— 表现就是「按了 ⌘, 一点反应都没有」。这是「独立窗口」方案的前置条件。
> 2. ⚠️ **开了多场景之后，系统往「文件」菜单里塞了一条 `New Window (⌘N)`，和我们的「新建」撞车 → 启动即崩**（`NSInvalidArgumentException: Replacement elements contain duplicates`）。
>    更阴的是：那条藏在子菜单分组 `com.apple.menu.new-item` 里，而 `AppDelegate.buildMenu` 原来那段「摘掉占了 ⌘N/⌘S 的旧项」只看了**第一层** children —— 等于没写。现在改成了递归（`takesOurShortcut`），撞车的整组摘掉。
>    **判据**：菜单是启动时构建的，所以这类冲突一律表现为「App 启动就崩」，`.ips` 里能看到 `AppDelegate.buildMenu(with:)` 那一帧（`~/Library/Logs/DiagnosticReports/`）。
> 3. **`#selector` 引用不到 `private` 方法** —— `MarkdownDocumentViewController.showSettings` 因此不能标 `private`；同理 `SceneDelegate.sceneDidDisconnect` 里那句注销要包 `#if targetEnvironment(macCatalyst)`，不然 iOS 编译报 `no member 'unregisterSettingsWindow'`（Catalyst 编过 ≠ iOS 编过，两边都要编）。
> 4. **控件在本机看不到时怎么验证**（没有辅助功能 / 屏幕录制权限，`osascript` 读菜单栏报 -10004、`screencapture` 报错）：
>    - 菜单结构：在 `buildMenu` 里临时 `UIPasteboard.general.string = dump`，跑一次 `pbpaste` 就能读回完整的菜单树（临时探针，验完删）。
>    - 窗口有没有真的开出来：`CGWindowListCopyWindowInfo`（写个 swift 脚本跑）按 owner + bounds 列窗口 —— 616×768 那扇就是设置窗口，1263×870 那扇是主窗口。

# 注册菜单项

> mac catalyst项目，全局按Command+, 跳转到设置ViewController，应该怎么实现？

在 Mac Catalyst 上，`Command+,` 是 macOS 系统级的"偏好设置"约定快捷键，**标准做法不是用 `UIKeyCommand` 全局监听，而是通过菜单栏（Main Menu）注册一个"Preferences…"菜单项**，并绑定快捷键。这样做的好处是：系统菜单栏天然支持这个快捷键，用户体验和原生Mac App完全一致，而且不用担心焦点在哪个输入框、哪个页面时快捷键失效的问题。

## 核心实现：UIMenuBuilder

### 1. 在 `AppDelegate` 或 `SceneDelegate` 中实现菜单构建方法

```swift
// AppDelegate.swift

override func buildMenu(with builder: UIMenuBuilder) {
    super.buildMenu(with: builder)
    
    // 确保是主菜单系统（避免在上下文菜单等场景重复构建）
    guard builder.system == .main else { return }
    
    // 创建"偏好设置…"菜单项（Command + ,）
    let preferencesCommand = UIKeyCommand(
        title: "偏好设置…",           // macOS 规范一般写 "Preferences…"
        action: #selector(openSettings),
        input: ",",                   // 对应逗号键
        modifierFlags: [.command]     // Command 修饰键
    )
    
    // 包装成菜单
    let preferencesMenu = UIMenu(
        title: "",
        options: .displayInline,      // 不显示子菜单标题，直接内联展示
        children: [preferencesCommand]
    )
    
    // 插入到 App 菜单（即菜单栏最左侧、App名称那个菜单）
    // .about 是系统预留的"关于"菜单项位置，我们插在它后面
    builder.insertSibling(preferencesMenu, afterMenu: .about)
}
```

### 2. 实现响应方法

因为 `UIKeyCommand` 的 `action` 要通过 responder chain 查找，一般把它写在 `AppDelegate` 里，或者写在某个始终存在于responder chain上的位置（比如根ViewController）：

```swift
extension AppDelegate {
    @objc func openSettings() {
        // 方式一：如果你的设置页是模态弹出
        guard let windowScene = UIApplication.shared.connectedScenes
            .first(where: { $0.activationState == .foregroundActive }) as? UIWindowScene,
              let rootVC = windowScene.windows.first?.rootViewController else {
            return
        }
        
        let settingsVC = SettingsViewController()
        let nav = UINavigationController(rootViewController: settingsVC)
        nav.modalPresentationStyle = .formSheet // Mac上常用的设置窗口样式
        rootVC.present(nav, animated: true)
    }
}
```

## 进阶：如果想用独立窗口打开设置（更像原生Mac App的体验）

很多Mac原生App的"偏好设置"是**独立的小窗口**，而不是模态弹出的sheet。Catalyst 可以通过 `UIWindowScene` 的多场景机制实现：

```swift
@objc func openSettings() {
    let activity = NSUserActivity(activityType: "com.yourapp.settings")
    UIApplication.shared.requestSceneSessionActivation(
        nil,
        userActivity: activity,
        options: nil,
        errorHandler: nil
    )
}
```

然后在 `SceneDelegate` 里判断这个 `userActivity`，为设置窗口单独配置一个 `UIWindowScene`：

```swift
func scene(_ scene: UIScene, willConnectTo session: UISceneSession, 
           options connectionOptions: UIScene.ConnectionOptions) {
    
    guard let windowScene = scene as? UIWindowScene else { return }
    
    if connectionOptions.userActivities.first?.activityType == "com.yourapp.settings" 
        || session.stateRestorationActivity?.activityType == "com.yourapp.settings" {
        
        // 配置成设置窗口：固定大小、不可全屏等
        #if targetEnvironment(macCatalyst)
        windowScene.sizeRestrictions?.minimumSize = CGSize(width: 480, height: 300)
        windowScene.sizeRestrictions?.maximumSize = CGSize(width: 480, height: 300)
        windowScene.titlebar?.titleVisibility = .visible
        windowScene.title = "偏好设置"
        #endif
        
        let settingsVC = SettingsViewController()
        let window = UIWindow(windowScene: windowScene)
        window.rootViewController = settingsVC
        self.window = window
        window.makeKeyAndVisible()
    }
}
```

## 几个注意点

1. **`buildMenu(with:)` 必须在 `AppDelegate` 或支持它的类里覆写**，这是 `UIResponder` 的方法，Catalyst/iPad会读取它来构建菜单栏。如果你的最低支持系统低于 iOS 13，要加条件判断。
2. **菜单快捷键的注册是"声明式"的**，不需要你自己写键盘事件监听代码，系统会自动处理全局捕获、以及和其他快捷键冲突检测。
3. **`afterMenu: .about`** 是遵循Mac约定的标准位置——"关于XXX"和"偏好设置…"紧挨着放在App菜单最上面，这是几乎所有Mac原生App的布局习惯，建议别随意改位置，否则显得不够"原生"。
4. **如果你的App同时跑在iPad上**（Catalyst和iOS共用一套代码），要注意 `UIKeyCommand` 在iPad上同样会生效（显示为快捷键），但iPad没有菜单栏，这时候需要你自己在界面上（比如导航栏按钮）另外提供入口，不能完全依赖快捷键。
5. **想要精确复刻"真正系统设置"的样式**（左侧Tab图标切换面板），可以参考系统偏好设置的UI结构自己用 `NSToolbar`（通过 `UIWindowScene.titlebar` 配合 `UISplitViewController` 或自定义TabBar）实现



# 独立窗口和模态弹出方案

> 如果是mac设备使用独立窗口，其他设备使用模态弹出的方式，给我最终版的包含核心代码的方案，太简单的swift代码使用伪代码即可

下面是整合方案：**Mac Catalyst 环境下用独立窗口打开设置，iPad/iPhone 等其他设备用模态弹出**，用 `#if targetEnvironment(macCatalyst)` 做编译期区分，核心逻辑清晰、可直接用。

## 2. SettingsManager：统一入口，内部区分平台

这是整个方案的核心。**关键思路：Mac用`requestSceneSessionActivation`拉起新场景（新窗口），非Mac直接present模态。**

```swift
// SettingsManager.swift

import UIKit

enum SettingsManager {
    
    static let settingsActivityType = "com.yourapp.settings"
    
    @objc static func openSettings() {
        #if targetEnvironment(macCatalyst)
        openSettingsAsWindow()
        #else
        openSettingsAsModal()
        #endif
    }
    
    // MARK: - Mac: 独立窗口
    #if targetEnvironment(macCatalyst)
    private static func openSettingsAsWindow() {
        // 如果设置窗口已经打开，激活它而不是重复创建
        let existingSession = UIApplication.shared.openSessions
            .first { $0.stateRestorationActivity?.activityType == settingsActivityType }
        
        if let existingSession = existingSession {
            UIApplication.shared.requestSceneSessionActivation(
                existingSession, userActivity: nil, options: nil, errorHandler: nil
            )
            return
        }
        
        let activity = NSUserActivity(activityType: settingsActivityType)
        UIApplication.shared.requestSceneSessionActivation(
            nil, userActivity: activity, options: nil, errorHandler: nil
        )
    }
    #endif
    
    // MARK: - iPad/iPhone: 模态弹出
    private static func openSettingsAsModal() {
        guard let rootVC = keyWindowRootVC() else { return }
        
        let settingsVC = SettingsViewController()
        let nav = UINavigationController(rootViewController: settingsVC)
        nav.modalPresentationStyle = .formSheet
        rootVC.present(nav, animated: true)
    }
    
    private static func keyWindowRootVC() -> UIViewController? {
        // 伪代码：取当前激活场景的 keyWindow.rootViewController
        // UIApplication.shared.connectedScenes 中找 activationState == .foregroundActive 的 UIWindowScene
        // 再取 windows.first(where: \.isKeyWindow)?.rootViewController
    }
}
```

## 3. SceneDelegate：处理Mac设置窗口的生命周期

只有Mac分支才需要新建独立场景，所以这部分逻辑用 `#if targetEnvironment(macCatalyst)` 包起来，非Mac环境完全不受影响。

```swift
// SceneDelegate.swift

func scene(_ scene: UIScene, willConnectTo session: UISceneSession,
           options connectionOptions: UIScene.ConnectionOptions) {
    
    guard let windowScene = scene as? UIWindowScene else { return }
    
    let isSettingsScene = connectionOptions.userActivities.first?.activityType == SettingsManager.settingsActivityType
        || session.stateRestorationActivity?.activityType == SettingsManager.settingsActivityType
    
    #if targetEnvironment(macCatalyst)
    if isSettingsScene {
        configureSettingsWindow(windowScene: windowScene)
        return
    }
    #endif
    
    // ------- 非设置窗口：走你原来的主窗口初始化逻辑 -------
    // 伪代码：按你项目原有方式初始化 window、rootViewController
}

#if targetEnvironment(macCatalyst)
private func configureSettingsWindow(windowScene: UIWindowScene) {
    // 固定窗口尺寸，不可全屏、不可调整大小（模拟系统偏好设置窗口的观感）
    windowScene.sizeRestrictions?.minimumSize = CGSize(width: 480, height: 320)
    windowScene.sizeRestrictions?.maximumSize = CGSize(width: 480, height: 320)
    
    windowScene.titlebar?.titleVisibility = .visible
    windowScene.titlebar?.toolbar = nil // 不需要工具栏的话隐藏
    windowScene.title = "偏好设置"
    
    let settingsVC = SettingsViewController()
    let window = UIWindow(windowScene: windowScene)
    window.rootViewController = settingsVC
    self.window = window
    window.makeKeyAndVisible()
}
#endif
```

## 4. AppDelegate：声明场景配置（Mac需要支持多场景）

Mac Catalyst 默认支持多窗口，这里不需要额外写 `UISceneConfiguration`，但要确保 Info.plist 或场景代理配置里 `UIApplicationSupportsMultipleScenes` 为 `true`（Catalyst默认就是true，一般无需改动，若关闭过要检查一下）。

```swift
func application(_ application: UIApplication,

                  options: UIScene.ConnectionOptions) -> UISceneConfiguration {
    
    let config = UISceneConfiguration(name: "Default Configuration", sessionRole: connectingSceneSession.role)
    config.delegateClass = SceneDelegate.self
    return config
}
```

# SettingsViewController的示例

> 写一个SettingsViewController的示例，如果是mac设备窗口左侧Tab切换多个设置面板，其他设备则还是UINavigationController套UIStackView或UITableView列表,点击push进详情，最好使用UIKit

下面给一个完整的方案：**统一的数据模型 + 平台分流的UI**。Mac端用 `UISplitViewController`（sidebar风格，仿系统偏好设置的Tab切换）；iPad/iPhone端用 `UITableView` + `UINavigationController` push。

## 1. 统一数据模型（两端共用）

```swift
// SettingsItem.swift

struct SettingsItem {
    let id: String
    let title: String

    let makeDetailVC: () -> UIViewController  // 点击后展示的详情页，闭包延迟创建

enum SettingsProvider {
    static func allItems() -> [SettingsItem] {
        return [

            },
            SettingsItem(id: "notification", title: "通知", icon: UIImage(systemName: "bell")) {
                NotificationSettingsViewController()
            },
            SettingsItem(id: "about", title: "关于", icon: UIImage(systemName: "info.circle")) {
                AboutViewController()
            }
        ]
    }
}
```

## 3. Mac端：UISplitViewController 侧边栏切换

使用 `UISplitViewController(style: .doubleColumn)` + `UICollectionView` compositional sidebar list，这是苹果官方推荐的仿系统设置侧边栏的标准写法（iOS 14+ / Catalyst 同样支持）。

```swift
// SettingsSplitViewController.swift
#if targetEnvironment(macCatalyst)

final class SettingsSplitViewController: UISplitViewController {
    
    private let items = SettingsProvider.allItems()
    
    override init(style: UISplitViewController.Style) {
        super.init(style: style)
```

## 结构关系图

```
SettingsViewController.make()
        │
        ├── [Mac] → SettingsSplitViewController
        │               ├── Primary: SettingsSidebarViewController (UICollectionView sidebar)
        │               └── Secondary: 当前选中的详情VC (如 GeneralSettingsViewController)
        │
        └── [iOS] → UINavigationController
                        └── Root: SettingsListViewController (UITableView)
                                └── push → 详情VC (如 GeneralSettingsViewController)
```

## 关键设计点说明

1. **`SettingsProvider.allItems()` 是唯一数据源**，Mac的侧边栏和iOS的列表读的是同一份数据，新增一个设置项只需要在这里加一条，两端自动同步，不用分别维护两份列表逻辑。
2. **详情页（如 `GeneralSettingsViewController`）完全平台无关**，不需要写任何 `#if targetEnvironment` 判断，因为不管是Mac的secondary列还是iOS的push目标，呈现的都是同一个普通`UIViewController`。
3. **Mac用的是 `UICollectionViewCompositionalLayout` 的 `.sidebar` 样式**，这是苹果从iOS14开始官方提供的标准侧边栏样式API，不需要自己写外观样式代码，视觉效果会自动匹配系统原生设置App的观感。
4. **只有 `SettingsSplitViewController` 和 `SettingsSidebarViewController` 用 `#if targetEnvironment(macCatalyst)` 包裹**，这样非Mac平台编译时这两个类根本不会被编进二进制，减少包体积也避免误用。
