# 代码块背景轮询

你现在的做法本质是「**轮询直到结果收敛**」：每 60ms 全量重算一遍所有装饰（代码块、引用条、复选框、表格），和上一轮比对，不稳定就继续，最多 30 次。这能工作，但有几个结构性问题。下面按收益从大到小说思路。

## 1. 把「轮询」换成「事件驱动」

轮询的根本问题是：你不知道排版什么时候稳定，所以靠猜。TextKit 2 其实有可以利用的信号：

- **`NSTextLayoutManagerDelegate` / `textViewportLayoutController.delegate`**：`textViewportLayoutControllerDidLayout(_:)` 会在每次 viewport 排版完成后回调。在这里刷新装饰，比定时器精准得多。
- **主动让排版稳定**：对需要画背景的范围调用 `textLayoutManager.ensureLayout(for:)`，强制把这些 fragment 排完，frame 就不再是估算值。这是最直接的解法，把「等它稳定」变成「让它现在就稳定」。
- 滚动停止、文档加载完成、内容编辑完成这几个时机各触发一次，而不是用重试兜底。

如果一定要保留重试，也应该是兜底，而不是主路径。

## 2. 不要每次全量计算，只算可见区域 + 缓存

现在每一轮都对整篇文档调用 `computeCodeBlockFrames / QuoteBarFrames / CheckboxFrames / TableScrollFrames`，文档一长就很重，还要重复 30 次。

- **只计算 viewport（加一点缓冲区）内的块**，屏幕外的块根本不需要画。这样既快，也绕开了「屏幕外 frame 是估算值」的坑，因为你压根不依赖它们。
- **块的语义信息与几何信息分离**：「哪些范围是代码块」只在文本变化时重新解析（可以在 parse/高亮阶段顺便产出），frame 只是语义范围到几何的映射。文本没变、只是滚动时，不要重新扫描语义，只重算可见块的 frame。
- 用 **文本变更的 dirty range** 做增量更新，只重算受影响的块。

## 3. 用更便宜的方式判断「稳定」

目前的比对是 `zip` + `allSatisfy` 逐个比较四类数组，成本不低，而且四类装饰绑在一个稳定性判断上，任何一类抖动都会拖着其他类一起重试。

- 只关注真正会漂移的东西（代码块 frame），其他类型如果不依赖屏幕外估算，就不必参与稳定性判断。
- 比较时加**容差**（比如 0.5pt 以内视为相等），避免浮点抖动导致永远「不稳定」。
- 更好的做法是只对比「第一个可见块的位置 + 总高度」这类摘要，而不是逐项对比。

## 4. 降低「错位被看见」的代价

即使稳定前的几帧位置不对，用户也未必会察觉，前提是你别让它闪：

- 装饰视图的 frame 更新用 `CATransaction.setDisableActions(true)`，避免隐式动画造成的飘移感。
- 不稳定期间可以对**屏幕外**的装饰直接不显示，只显示可见区域内已稳定的。
- 考虑把背景画在 **`NSTextLayoutFragment` 的绘制层**（自定义 `NSTextLayoutFragment` 子类，在 `draw(at:in:)` 里先画背景再调用 super）。这样背景由 TextKit 自己在正确的位置绘制，天然跟随排版，**根本不需要事后算 frame 再对齐**。这是最彻底的方案：代码块、引用条都可以走这条路，TextKit 2 官方就是鼓励这样做的。复选框、表格横滚视图因为是真实子 view，才保留 frame 计算那套。

## 5. 调度层面的小优化

- **合并触发**：编辑、滚动、重试都在调这个函数，用一个 coalescing 的调度（`needsDecorationRefresh` 标记 + 下一个 runloop 或 `CADisplayLink` 统一刷）避免同一帧多次重算。
- **重试用递增间隔**（60 → 100 → 200ms）而不是固定 60ms，或者限制总时长而不是次数。
- 每次新触发应当**取消**上一轮挂起的重试，否则快速编辑时会叠出多条重试链并行跑。`codeBlockRetryCount` 的清零时机也要小心，现在多链并行时计数是混乱的。
- 切换文档时重置状态，防止旧文档的 frame 缓存影响新文档的第一次对比。

## 建议的落地顺序

1. 先做 **只算可见区域**（改动小、收益立竿见影）。
2. 再接 **viewport layout 回调 + ensureLayout**，把大部分重试去掉。
3. 有余力的话，把代码块和引用条背景迁移到 **自定义 `NSTextLayoutFragment` 绘制**，从根上消除对齐问题，同时删掉大量 frame 计算和 position 代码。
