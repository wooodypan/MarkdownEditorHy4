这个比单纯的"整块竖条"复杂一点，因为**嵌套引用**要求竖条本身也要分层——外层一条、内层再加一条，而且两条竖条的高度覆盖范围不一样（外层竖条覆盖整个引用，内层竖条只覆盖内层引用那一段）。核心思路仍然是复用你现有的"overlay 层 + 按 blockID 合并 fragment rect"机制，但要按**嵌套深度**分别打标记、分别画。

## 核心思路：竖条数量 = 引用嵌套深度，每层独立计算 rect

不要把"引用竖条"当成一个整体属性，而是当成一个**数组**——每个字符/行携带"它被多少层 `>` 包裹、每一层分别是哪个 `BlockQuote` 节点"。

### 第一步：渲染阶段——按嵌套深度打标记，而不是布尔值

```swift
/// 一个字符所处的引用嵌套链，从外到内排列。
/// 例如 "> > 内层引用" 这一行，quoteChain = [outerQuoteID, innerQuoteID]
struct QuoteLevelInfo {
    var quoteChain: [UUID]   // 每一层 BlockQuote 节点的稳定 ID，按嵌套顺序
}

mutating func visitBlockQuote(_ blockQuote: BlockQuote, depth: Int = 0, chain: [UUID] = []) -> NSAttributedString {
    let quoteID = UUID()  // 或用该节点在 source 中的起始位置派生稳定 ID，保证增量渲染时同一引用块 ID 不变
    let newChain = chain + [quoteID]

    let result = NSMutableAttributedString()
    for child in blockQuote.children {
        if let nestedQuote = child as? BlockQuote {
            // 递归处理嵌套引用，chain 继续累加
            result.append(visitBlockQuote(nestedQuote, depth: depth + 1, chain: newChain))
        } else {
            var childVisitor = self
            result.append(childVisitor.visit(child))
        }
    }

    let fullRange = NSRange(location: 0, length: result.length)
    result.addAttribute(.markdownQuoteChain, value: newChain, range: fullRange)

    let style = theme.paragraphStyle(for: .blockQuote(depth: depth))  // 见下方缩进说明
    result.addAttribute(.paragraphStyle, value: style, range: fullRange)
    result.addAttribute(.foregroundColor, value: theme.colors.blockQuoteText, range: fullRange)
    return result
}
```

**关键点**：`markdownQuoteChain` 存的是**数组**而不是单个 ID/深度数字，因为要支持"每一层竖条独立计算自己覆盖的 rect"——内层引用只出现在文档的一部分范围内，外层引用覆盖更大范围，两者的 bounding rect 必须分开算，不能用一个"深度=2 画粗一点/画两条紧贴的线"这种简化处理（那样在内层引用结束、只剩外层引用继续的地方会出错）。

### 第二步：缩进随深度递增，为每一层竖条预留空间

```swift
extension MarkdownTheme {
    func paragraphStyle(for kind: ParagraphStyleKind) -> NSParagraphStyle {
        let style = NSMutableParagraphStyle()
        if case .blockQuote(let depth) = kind {
            let d = CGFloat(depth + 1)
            // 每多一层嵌套，整体再向右缩进一个「竖条宽度 + 层间距」
            style.headIndent = blockQuote.contentLeadingInset * d
            style.firstLineHeadIndent = style.headIndent
        }
        return style
    }
}
```

这样第 1 层引用文字整体缩进一份，第 2 层再多缩进一份，视觉上天然形成"内层比外层更靠右"的效果，竖条画在各自缩进的左边界上。

### 第三步：Overlay 层——按 `(quoteID, 该层在 chain 中的位置)` 分别合并 rect 并画线

```swift
extension MarkdownTextView {
    func updateBlockQuoteBars() {
        // key: quoteID, value: (该层在 chain 中的 index, 合并后的 bounding rect)
        var barsByQuoteID: [UUID: (levelIndex: Int, rect: CGRect)] = [:]

        textLayoutManager.enumerateTextLayoutFragments(from: nil, options: [.ensuresLayout]) { fragment in
            guard let chain = fragment.quoteChain, !chain.isEmpty else { return true }
            let frame = fragment.layoutFragmentFrame
            // chain 里的每一层都要各自累加自己的 rect——
            // 外层 quoteID 的 rect 要覆盖「所有包含它的行」（包括内层引用占据的行），
            // 内层 quoteID 的 rect 只覆盖内层引用自己占据的行
            for (index, quoteID) in chain.enumerated() {
                var existing = barsByQuoteID[quoteID]?.rect ?? .null
                existing = existing.union(frame)
                barsByQuoteID[quoteID] = (index, existing)
            }
            return true
        }

        blockQuoteBarLayer.updateBars(barsByQuoteID, theme: theme)
    }
}

final class BlockQuoteBarLayer: UIView {
    func updateBars(_ bars: [UUID: (levelIndex: Int, rect: CGRect)], theme: MarkdownTheme) {
        for (quoteID, info) in bars {
            let layer = shapeLayer(for: quoteID)  // 复用或新建，与代码块背景同一套复用机制
            let x = theme.blockQuote.barLeadingInset
                  + CGFloat(info.levelIndex) * theme.blockQuote.contentLeadingInset
            layer.frame = CGRect(x: x, y: info.rect.minY,
                                  width: theme.blockQuote.barWidth, height: info.rect.height)
            layer.backgroundColor = theme.colors.blockQuoteBar.cgColor
            layer.cornerRadius = theme.blockQuote.barCornerRadius
        }
    }
}
```

这样得到的效果正好符合你给的例子：

```
│ 这是一段引用文本。          ← 只有 1 条竖条（levelIndex 0）
│ 外层引用
│
│ │ 内层引用                 ← 2 条竖条：外层竖条继续延伸 + 内层竖条只在这一行
```

外层那条竖条会**贯穿整个引用块**（包括内层引用占据的那几行），内层那条竖条**只出现在内层引用自己的行范围内**，两条竖条左右错开一个 `contentLeadingInset` 的距离——这正是你截图里那种"越往内嵌套竖条越靠右、外层竖条不间断"的标准效果。

## 引用块内部的富内容：加粗、无序列表如何处理

按你的要求，这两种先支持，思路是**不新增机制，直接复用你已有的 `visitStrong`/`visitUnorderedList` 逻辑**，只是这些内容出现在 `BlockQuote.children` 遍历过程中：

```swift
mutating func visitBlockQuote(_ blockQuote: BlockQuote, depth: Int = 0, chain: [UUID] = []) -> NSAttributedString {
    let quoteID = ...
    let newChain = chain + [quoteID]
    let result = NSMutableAttributedString()

    for child in blockQuote.children {
        let rendered: NSAttributedString
        switch child {
        case let nested as BlockQuote:
            rendered = visitBlockQuote(nested, depth: depth + 1, chain: newChain)
        case let paragraph as Paragraph:
            rendered = visitParagraph(paragraph)   // 内部已经会处理 Strong/Emphasis 等 inline
        case let list as UnorderedList:
            rendered = visitUnorderedList(list)    // 复用现有列表渲染，圆点/弱化 `-` 逻辑不变
        default:
            rendered = defaultVisit(child)         // 其余类型（代码块、有序列表等）先走兜底：
                                                     // 原样保留文字，不做特殊装饰，满足「暂不支持」的要求
        }
        result.append(rendered)
        result.append(NSAttributedString(string: "\n"))
    }

    // 统一给整段打 quoteChain 标记（包括子节点内部已经打好的 inline 样式，
    // 因为 addAttribute 只加不减，不会覆盖 Strong/列表已经设置的 font/color）
    result.addAttribute(.markdownQuoteChain, value: newChain,
                         range: NSRange(location: 0, length: result.length))
    ...
    return result
}
```

**关键点**：`.markdownQuoteChain` 这个 attribute 是"叠加"在已经渲染好的子内容之上的（比如列表圆点的绘制标记、加粗的字体，都是子节点渲染时已经设置好的 attribute），引用竖条的绘制发生在 overlay 层、代码块背景和列表圆点也是各自独立的 overlay/绘制逻辑，几种装饰互不冲突，可以同时叠加显示——这也是当初把"竖条""背景""圆点"都设计成基于 attribute 标记 + 独立绘制、而不是互相耦合的写死逻辑的好处，现在加嵌套引用+列表组合不需要改动列表或加粗的任何代码。

对于你明确说"暂不支持"的引用内代码块、链接特殊装饰、有序列表：`defaultVisit` 兜底会把这些内容的**原始字符原样保留**（满足"全字符可见"的底线要求），只是不会有代码块背景、复制按钮这些额外装饰——文字还是对的，只是暂时没有视觉增强，后续要支持时按同样模式在 `visitBlockQuote` 的 `switch` 里加一个 `case` 分支即可，不需要动竖条机制本身。

## 和现有架构的复用关系一览

| 需要的能力 | 复用哪部分 |
|---|---|
| 多层竖条按嵌套分别绘制 | 沿用"代码块背景"那套 `CAShapeLayer` overlay + 按 ID 合并 `layoutFragmentFrame` 的机制，只是 key 从单个 blockID 换成 quoteChain 数组的每一项 |
| 缩进随深度递增 | `NSParagraphStyle.headIndent`，与代码块的 `innerPadding` 是同一类手法 |
| 加粗、列表在引用内正常工作 | 直接复用 `visitStrong`/`visitUnorderedList`，无需改动 |
| 复制时竖条不出现在粘贴结果里 | 竖条本身不是插入字符（不像图片/表格附件），而是纯 overlay 绘制，天然不在 `NSAttributedString` 字符序列里，复制逻辑不需要任何特殊处理 |
| 增量渲染 | 整个顶层 `BlockQuote`（含所有嵌套层）仍然是一个 `MarkdownBlock`，编辑引用内任意内容按现有规则（11.2 节"编辑发生在引用块内部→扩展到整个引用块"）重渲染即可，chain/quoteID 在同一次渲染内重建，不影响块粒度增量策略 |

需要额外在 `MarkdownTheme.BlockQuote` 里补一个字段：

```swift
struct BlockQuote: Equatable {
    var barWidth: CGFloat = 3
    var barLeadingInset: CGFloat = 8
    var contentLeadingInset: CGFloat = 20   // 复用：既是文字缩进单位，也是层间竖条水平间距
    var barCornerRadius: CGFloat = 1.5
    var maxRenderedDepth: Int = 4           // 建议加一个深度上限，超过后 defaultVisit 兜底为纯文本，
                                              // 避免极端嵌套（用户手滑打了 10 个 >）导致缩进挤没了内容区域
}
```
