插入图片，换个方式起名，换个地方存放

往编辑器里粘贴一张图，它会先在磁盘上落成一个文件，正文里写的只是这个文件的路径。这次改动动了这条路上的两处地方，一处是文件叫什么名字，一处是文件落在哪个文件夹。

## 名字从随机改成自己挑

改之前，文件名长这样，`pasted-` 后面跟一串随机 UUID，后缀固定写死 `.png`。

```
pasted-4F2C9A71-8B3D-4E5F-9A6C-1D2E3F4A5B6C.png
```

现在设置页里能选三种取法，选中的那种决定前面那一截叫什么；不管选哪种，后缀都跟着图片的真实格式走，可能是 `png`，可能是 `jpg`，也可能是 `gif` 或者 `heic`。

| 设置里选的 | 落到磁盘上 |
| --- | --- |
| 使用原始文件名（默认） | `截屏2026-10-15.jpg` |
| 使用当前时间 | `20261015_172442.jpg` |
| 使用文件 MD5 哈希 | `9b7f3c1e05a64d8e2b1f7a3c9d0e5f68.jpg` |

默认选「原始文件名」，因为从 Finder 里拖过来的图本来就带着一个有意义的名字，没理由把它丢掉。

这一档有个缺口。只有从 Finder 里复制过来的图才带着原始文件名。截图、网页里的图、别的 App 直接塞进剪贴板的一张图，都没有名字可用，这些会退回用 MD5 哈希。所以同一个目录里可能混着两种风格的名字。

「当前时间」用的是落盘那一刻的本地时间，格式是「年月日_时分秒」，一眼看得出图是什么时候粘进来的。这里的年月日**不跟随系统地区**，固定按公历印。换个地区的话 `yyyy` 会印成佛历那种年份，名字照样能存、也不会重名，但人一看就懵，而且很难查，所以不让它跟随。

最后一种 MD5 是按内容算出来的指纹。它把任意长度的一堆字节压缩成固定长度的一串字符，同一堆字节算出来永远一样，改一个字节结果就完全不同。拿它当名字最直接的好处是同一张图粘贴两次只会留下一个文件，磁盘上不会躺着两份一模一样的副本。这里只把它当指纹用，不涉及任何加密强度的问题。

## 名字被占用了就改用哈希

不管选了哪种取法，落盘之前都会先看一眼目标目录里有没有同名文件。有的话这个名字就不能用了，改用 MD5 哈希兜底。

不直接覆盖，是因为占着那个名字的多半是用户自己的另一张图。也不兴加「-1」「-2」往后排，那样同一张图反复粘会攒出一串副本，而哈希名字天然是「内容一样就是同一个文件」。

所以「原始文件名」这一档连着粘两次同一张图，磁盘上会是两份，先来的叫 `截屏2026-10-15.jpg`，后来的叫 `<哈希>.jpg`。

## 原始文件名里的空格会被换掉

原始文件名洗过一遍才会用。空格、`#`、`?`、`%`、尖括号、引号、竖线、冒号、斜杠这些字符一律换成 `-`，两头的 `-` `.` 空格也会掐掉。

换掉是有原因的，其中空格最要命。markdown 的图片地址写成 `![](assets/我的 图.png)` 是解析不出来的。标准规定这种不写成尖括号的地址里不能有空格，解析器会把它切成「地址是 `assets/我的`，后面跟了一个看不懂的标题」，图就显示不出来了。剩下的几个各有各的麻烦。`#` 和 `?` 会被当成地址里的锚点和查询串，`%` 会被后面的 URL 编码再编一遍，尖括号会被误认成包裹符，引号会把导出的 HTML 属性截断，竖线会把表格截断，冒号会让相对路径被当成「协议头」。

换成 `-`，既躲开这些坑，名字也还是看得懂的。

## 后缀为什么也要跟着变

原来后缀写死 `.png`，因为它真的是把图片重新编码成 PNG 再存的。那段代码从 `UIPasteboard.general.image` 拿图，这个属性交给你的是一张已经解码好的图片对象，而图片对象本身不记得自己原来是 JPEG 还是 HEIC，你从它身上只能再编码出 PNG。

代价是复制来的 JPEG 会被撑成好几倍大的 PNG，页面上顺下来的动图只剩下第一帧。

现在改成直接去剪贴板里把真正的图片字节拿出来。字节拿到手里不去动它，什么格式进来就什么格式写盘，后缀自然也跟着算出来的格式走。

怎么知道哪一条才是图片？这里一开始判断错了，详见后面「找图片这一步返过工」那一节。现在分三步走。先看剪贴板里有没有一个文件地址，有就按地址去读原文件；读不到就按类型挨个问剪贴板要（知道原文件是什么格式就先要那个格式）；再要不到才退回自己编码。

JPEG 有个小地方要圆一下。系统给的标准后缀是 `jpeg` 四个字母，而我们平时电脑里的文件基本都叫 `.jpg`。代码里做了一次替换，落到磁盘上还是熟悉的三个字母。

## 找图片这一步返过工

改完之后出过一个岔子。从 Finder 里复制一张图片，粘进编辑器，图片文件确实躺在 `assets` 里，名字也对，可就是打不开。用十六进制工具打开一看，里面根本不是图片。

问题出在「怎么判断剪贴板里的哪一条数据是图片」。当时的写法是让系统的 ImageIO 试着解一下，解得开就认。想法没错，错在这个函数比想象中宽容。它叫 `CGImageSourceCreateWithData`，是个**懒解析**的函数，你递给它任何一堆非空的字节，它都先说「收到」并交回一个对象，并不当场告诉你这堆字节到底是什么。真正会露馅的是下一步，问它「你是什么格式」，这一步才答得出来。

也就是说，「试着解一下」等于没试，代码实际做的事变成了「剪贴板里第一条非空数据就是图」。

偏偏从 Finder 复制图片时，剪贴板里排在最前面的那条不是图片，是一个**文件地址**，内容就是 `file:///…` 这样一串文本，几十个字节。它被当成了图片的字节写进了文件。后缀那边同样问不出格式，代码按兜底规则写了 `.png`。于是一个装着路径文本的 `.png` 诞生了。文件在、名字对、体积不对、点开就报错。

从这里能顺手解释为什么以前没事。旧代码走的是 `UIPasteboard.general.image`，系统会先按那个地址把图片读出来再交给你，绕开了「挑哪一条」这个判断，自然挑不错。代价是那张图已经被解码过一次，你只能再编码成 PNG 存下去，也就是前面说的那个体积问题。

改法有两处。判断图片时多问一句「你是什么格式」，答不出格式的就不认，这样文件地址那串文本就被挡在外面了。另外，既然剪贴板里本来就带着文件地址，那就干脆按地址把原文件读出来，这是唯一能保证「就是原来那份字节」的路子，剪贴板里另外十几种格式都是系统现转的。读原文件失败（沙箱没给权限之类）才回头去按类型要。

顺便补了一条自愈。文件名的规矩是同名跳过，免得白写一遍，但原来判断的依据是「同名文件在不在」。要是磁盘上留着一个同名但空着的残骸，就会被一直当成成品交出去，图永远打不开，怎么重粘都还是它。现在判断的依据换成「字节数对不对」，残骸会被正常覆盖掉。写完还会再核一遍大小，写盘没报错但落下去的东西不对时，宁可当成没存成，也不把一条指向坏文件的路径插进正文。

## 微信截屏的图粘不进来，毛病不在取图

改完之后又冒出一个岔子。用微信截屏，点复制，回到编辑器按粘贴，光标不动，正文一个字都不多，也没有任何提示，就像这一下根本没发生过。

第一个怀疑的还是取图那一步。它刚返过工，症状也像，图没取到，自然插不进来。这一轮真去改了。

剪贴板里一格一格地排着，一格放一段内容。原来的代码只看第一格，这回改成每一格都问一遍。翻格子的时候，格子里的东西未必长一个样。有的直接给一份原始字节，一个字节都没重编码过；有的给一张系统已经解码好的图片对象。以前只认前一种，这回两种都收。最后那道兜底问的是「剪贴板上的那张图」，对应的属性是 `image`，它一样只看第一格；这回换成「剪贴板上的图片数组」，对应的 `images` 会把所有格子里的图一起给你。

这么改不算错，它确实挡掉了几种真会取不到图的场合。可微信这一张还是粘不进来。

那就别再猜，先把现场拿到手。趁剪贴板里还留着微信那张图，把里面的东西整个倒出来看。结果干净得有点意外。剪贴板里只有一个条目，类型也只有 `public.png` 一种。那 65535 字节是一张完整的 PNG，分块一路排到结尾的 IEND。交给系统解码，能拿到一张 140×348 的正常图片。把这堆字节喂回我们自己的取图逻辑，也一样一个不差地取出来。

图就在里面，取得到，一个字节都没错。毛病只能在更前面，在「这次粘贴压根没被叫起来」这个位置上。

顺着这个方向很快就对上了。粘贴在 Mac 上是一条菜单项，菜单项亮不亮，由系统先问一句「你现在能不能干这个活」。系统默认的判据是**剪贴板里有没有文字**。剪贴板里只放了一张图、一个字都没放的场合，这句问话得到的答案就是没有，菜单项被判成不能干，整条灰下去，快捷键按了也什么都不发生。

微信截屏只往剪贴板里放图片，一个字都不放，正好撞在这个判据上，macOS 自带的截图也是同一个毛病。

那以前从 Finder 复制图片为什么一直好好的？因为那会儿剪贴板里除图片之外，还**并排放着一串文件地址**，内容就是 `file:///…`。这串地址在系统眼里就是文字，「有没有文字」于是答有，粘贴一直亮着。一条歪打正着的路，谁也没注意到它一直在替我们兜着。

修法落在 `MarkdownTextView+Clipboard.swift` 里那个 `canPerformAction` 覆写上，剪贴板里有图就把粘贴点亮，别的场合照旧交给系统去判断。新加的是中间那三行。

这一手是照着 MiaoYan 的 iOS 端编辑器抄的，它那个 `MarkdownEditorView` 在同一个位置覆写了这个方法。真因还是上面那些实测量出来的，MiaoYan 省掉的只是「该往哪儿修」这一步。

```swift
override func canPerformAction(_ action: Selector, withSender sender: Any?) -> Bool {
    if action == #selector(paste(_:)), UIPasteboard.general.hasImages {
        return true
    }
    return super.canPerformAction(action, withSender: sender)
}
```

### 这个毛病是怎么量出来的

这次没再靠命令行探针，直接在真 App 里量。启动时右边还没有打开的文档，窗口里一个编辑器都没有，那就现场造一个挂进真窗口，让它成为第一响应者，再问它那句话，然后真的调用一次粘贴。

量出来两组数字。

| 剪贴板里装的 | 改动前 | 改动后 |
| --- | --- | --- |
| 只有一张图 | 不能粘 | 能粘 |
| 只有一段文字 | 能粘 | 能粘 |

第一行改动前是不能粘，但把粘贴硬调一次，**内容是能贴进去的**，正文尾部多出 `![粘贴的图片](attachments/….png)`。这说明活儿本来就能干，之前卡住的只是入口那一下。

这个诊断程序是临时写的，量完就删了，仓库里没留。

## 存哪儿变成一个选项

设置页新增了一组「插入图片」。第一行是一个按钮，点开是四项菜单，选中的那一项打勾。

| 菜单里写的 | 图片存到哪 | 正文里写成什么 |
| --- | --- | --- |
| 复制到当前文件夹（./） | 和笔记并排放在同一层 | `截屏.jpg` |
| 复制到 ./assets 文件夹 | 笔记旁边的 assets 子目录 | `assets/截屏.jpg` |
| 复制到与笔记同名的文件夹 | 笔记叫「游记.md」就是「游记/」 | `游记/截屏.jpg` |
| 复制到指定路径… | 你自己挑的那个文件夹 | 完整路径，比如 `/Users/你/图库/截屏.jpg` |

表里的「截屏.jpg」只是举例，实际叫什么由上面那个文件名设置决定。这两项互不影响，哪个目录都能配哪种名字。

前三项写的都是相对路径，图片跟着笔记一起挪窝也不会断。第四项的图片在笔记目录之外，相对路径表达不了它的位置，只能写完整路径。

默认选的是 `./assets`。原来的行为是存进 `Documents/attachments/`，图片和正文分开摆，笔记目录一眼看过去还是清清爽爽的一排 `.md`。「当前文件夹」会把目录塞满图片，「指定路径」又需要你先做一次选择，所以都不适合当默认。

## 为什么「指定路径」只有 Mac 上能选

选文件夹靠的是系统的文件夹选择框。iPhone 和 iPad 上这套东西走的是「文件」App，用户很容易挑到一个自己以后再也找不到的地方，图片存进去了，正文里只留下一长串路径，看着像图片丢了。

与其给一个容易踩坑的入口，不如这一项在手机和平板上干脆不出现。判断方式是编译期的 `#if targetEnvironment(macCatalyst)`，所以那一行只在 Mac 的设置页里存在。

## 挑文件夹复用了导出那块面板

导出图片、HTML、PDF 的时候，会弹一个系统面板让你选存放位置。设置页里选文件夹用的是同一个系统类 `UIDocumentPickerViewController`，两处不一样的地方都跟「导出」这个用途有关。类型参数从「某个文件类型」换成文件夹类型，`asCopy` 传 `false`，因为这里要拿的是那个文件夹本身，不是它的一份副本。

这块面板在 Mac 上长成原生对话框的样子，左边一列位置，右边列文件夹，选完点「打开」。按钮上显示当前选中的完整路径，路径太长会从中间截断，开头留着磁盘，结尾留着文件夹名。

## 写不进去的时候退到 ./assets

指定路径最怕的是文件夹被用户删了或者挪走了。这时候代码不会静默失败让粘贴像点了没反应，而是退到 `./assets` 把图存下来，同时在状态栏说一句「写不进某某文件夹，这张先存到了 ./assets」。

另一种情况是你还没选过文件夹就选了这一项，处理方式一样，提示语换成「还没选过『指定路径』的文件夹」。

## 改动落在哪些文件

包里的编辑层（`MarkdownEditor/`）动了两个文件。`MarkdownPasteboardController` 增加了一个 `imageFileWriter` 回调，粘贴图片时不再自己决定存哪儿，而是把这份字节交给 App 层，由 App 回答「存哪儿、正文里写什么」。回调递两样东西过去，图片的字节，和图片原来的文件名（没有就是空）。文件名是从剪贴板里那个文件地址上取的，只有 Finder 复制过来的图才有，它和「用哪份字节」是两件事，就算后来用的是系统转出来的那份格式，用户心里这张图还是叫原来那个名字。这个写法和旁边那个「剪贴板富文本转 markdown」的口子是一个套路，组件本身不认识设置页，将来单独开源出去也不会拖着一堆 App 的东西。

新文件 `MarkdownImageFileStore` 只管算名字和写盘，一行 UI 都不碰。三种取名规则和「同名就换哈希」都在这里，`MarkdownImageNaming` 这个枚举就是三种规则的清单。它的方法都标了 `nonisolated`，意思是这些活没理由必须挤在主线程上干，将来想挪到后台队列也不用改它。

App 层新增 `ImageAssetStore`，按设置算出目标文件夹和正文路径，并把设置里的文件名规则翻译成 `MarkdownImageNaming` 交给上面那层。它和编辑层之间只隔着 `imageFileWriter` 这一个函数。

设置那边动了三个文件。`MarkdownEditorSettings` 里多了 `ImageInsertionMode` 和 `ImageNameMode` 两个枚举、以及三个配置项，`SettingsViewController` 里多了那一组界面，`MarkdownDocumentViewController` 在装配编辑器时把回调接上。

还有一处小改动落在 `MarkdownTextView+Clipboard.swift`，就是那个「剪贴板里有图就让粘贴亮起来」的判断。它和旁边接管复制剪切粘贴的三个方法放在同一个文件里，剪贴板相关的接触面一眼可见。

设置页里「存哪儿」和「叫什么名字」两行长得一样，都是「按钮上写着当前选项、点一下弹菜单」。这两行的控件用同一个私有方法造，省得同一段按钮配置写两遍。

配置项有件事和别的设置不一样。改字号、改配色那些设置都会发一条「配置变了」的广播，因为屏幕上的文字要当场重排。图片存放位置和文件名这两项不用发，它们只影响下一次插入的图，屏幕上那篇一个字都不用动。广播出去只会白重排一次整篇文档，大文档上肉眼看得见地卡一下。

## 现在还不能做的三件事

笔记改名的时候，图片和它所在的文件夹不会跟着走。左栏的重命名只动 `.md` 文件本身。要是选了「与笔记同名的文件夹」，改完名图片目录还挂着旧名字，正文里的路径就断了。想处理得让重命名同时搬目录、改正文，这次没做。

另外有一种配置能出现的边角情况。在 Mac 上设好「指定路径」，配置文件又跟着到了 iPhone，手机上的按钮会显示成「复制到指定路径…」。菜单里照样能翻到这一项，图片却存不进那个文件夹，于是退到 `./assets`，并在状态栏说一句，不会写丢。

还有一种是剪贴板里只有一个文件地址、别的什么都没有。这一种在 Mac 上根本读不到，系统没把这种剪贴板桥接给编辑器，所以取不到图。现实里很少见，从 Finder 复制的文件旁边总会带着一份预览图，那种是能取到的。
